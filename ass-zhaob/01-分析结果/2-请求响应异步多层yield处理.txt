⏺ 三层 Yield 机制详解

  什么是 Yield？

  Yield 基础概念：
  # 普通函数：一次性返回所有结果
  def get_numbers():
      result = []
      for i in range(5):
          result.append(i)
      return result  # 一次性返回 [0,1,2,3,4]

  # 生成器函数：逐步产生结果
  def get_numbers_generator():
      for i in range(5):
          yield i  # 每次调用返回一个值，下次调用继续执行

  # 使用
  gen = get_numbers_generator()
  print(next(gen))  # 0
  print(next(gen))  # 1
  # ... 逐步获取

  Yield 的核心特性：
  - 惰性计算：只在需要时计算下一个值
  - 状态保持：函数状态在 yield 之间保持
  - 内存效率：不需要存储所有结果

⏺ 第三层 Yield 的核心作用：

  def await_result(self):
      # 1. 当后台任务还在运行时
      while self.is_running():  # 检查线程是否完成
          while True:
              chunk = self.pop_chunk()  # 从内存队列取出数据
              if chunk is not None:
                  yield chunk  # 直接 yield 给 HTTP 响应
              else:
                  break  # 队列空了，继续循环检查

      # 2. 后台任务完成后，处理剩余数据
      while True:
          chunk = self.pop_chunk()
          if chunk is None:
              break
          yield chunk

  线程同步机制：

  # 生产者线程（后台）
  def run_task_cache(self, ...):

          self.chunk_list.append(chunk)  # 放入内存队列

  # 消费者线程（主线程，HTTP 响应）
  def await_result(self):
      while self.is_running():
          chunk = self.pop_chunk()  # 从队列取出
          if chunk:
              yield chunk  # 给前端

  为什么需要三层 Yield？

  第一层存在的原因：

  - LLM 输出复杂：需要解析 additional_kwargs 和标签
  - 统一接口：不同 LLM 的输出格式统一化
  - 内容分离：区分普通内容和推理内容

  第二层存在的原因：

  - 业务逻辑：添加 type、状态信息等业务字段
  - 格式转换：转换为 SSE (Server-Sent Events) 格式
  - 累积处理：收集完整内容用于后续处理

  第三层存在的原因：

  - 异步解耦：后台处理与 HTTP 响应分离
  - 流式传输：实时将数据推送给前端
  - 线程安全：通过内存队列实现线程间通信

  三层 Yield 机制是一个精心设计的流式数据处理管道：

  核心设计思想

  3. 实时传输：用户可以立即看到处理进度

  - 系统性能：避免长时间阻塞 HTTP 请求
