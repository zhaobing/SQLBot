⏺ SQLBot Chart生成机制详解

  整体流程概述

  SQLBot的chart生成机制是一个完整的前后端协作系统，从自然语言查询到最终的可视化图表展示，涉及多个环节的智能处理和数据流转。

  后端Chart生成机制

  1. SQL生成与执行（llm.py:run_task()）

  SQL生成阶段（第979-987行）：
  sql_res = self.generate_sql(_session)
  for chunk in sql_res:
      full_sql_text += chunk.get('content')
      # 实时返回SQL生成过程
      yield 'data:' + orjson.dumps({'content': chunk.get('content'), 'reasoning_content': chunk.get('reasoning_content'), 'type': 'sql-result'}).decode() + '\n\n'

  数据库查询执行（第1051行）：
  result = self.execute_sql(sql=real_execute_sql)
  self.save_sql_data(session=_session, data_obj=result)

  这里的关键是 self.execute_sql() 方法（第858-876行），它会：
  - 连接到指定的数据源
  - 执行SQL查询
  - 返回包含字段信息和数据的结果集
  - 限制返回数据量（最多1000行）

  2. Chart配置生成（第1086-1099行）

  chart_res = self.generate_chart(_session, chart_type)
  for chunk in chart_res:
      full_chart_text += chunk.get('content')
      # 实时返回chart生成过程
      yield 'data:' + orjson.dumps({'content': chunk.get('content'), 'reasoning_content': chunk.get('reasoning_content'), 'type': 'chart-result'}).decode() + '\n\n'

  chart = self.check_save_chart(session=_session, res=full_chart_text)

  Chart生成过程：
  - 基于SQL查询结果数据结构
  - 分析数据特征和关系
  - 智能推荐最适合的图表类型
  - 生成图表配置信息（坐标轴、数据映射等）

  3. Chart配置格式

  后端生成的chart配置包含：
  {
    type: ChartTypes  // 'table', 'column', 'bar', 'line', 'pie'
    title: string
    axis: {
      x: { name: string; value: string }
      y: { name: string; value: string }
      series: { name: string; value: string }
    }
    columns: Array<{ name: string; value: string }>
  }

  4. 实时数据流传输

  后端通过Server-Sent Events (SSE)实时推送处理进度：
  - sql-result: SQL生成过程
  - sql-data: 数据查询完成
  - chart-result: Chart配置生成过程
  - chart: 最终Chart配置
  - finish: 处理完成

  前端Chart渲染机制

  1. 数据接收与处理（ChartAnswer.vue）

  前端监听SSE流，实时接收后端推送的数据：
  case 'chart-result':
    chart_answer += data.reasoning_content
    _currentChat.value.records[index.value].chart_answer = chart_answer
    break
  case 'chart':
    _currentChat.value.records[index.value].chart = data.content
    break
  case 'sql-data':
    getChatData(_currentChat.value.records[index.value].id)
    break

  2. Chart组件层级结构

  ChartAnswer.vue
  └── ChartBlock.vue
      └── DisplayChartBlock.vue
          └── ChartComponent.vue

  ChartBlock.vue：Chart容器组件，提供工具栏、图表类型切换、导出等功能

  DisplayChartBlock.vue：数据适配层，将后端数据转换为图表渲染所需格式：
  const xAxis = computed(() => {
    if (chartObject.value?.axis?.x) {
      return [chartObject.value.axis.x]
    }
    return []
  })

  ChartComponent.vue：核心渲染组件，通过工厂模式获取具体图表实例：
  function renderChart() {
    chartInstance = getChartInstance(params.type, chartId.value)
    if (chartInstance) {
      chartInstance.init(axis.value, params.data)
      chartInstance.render()
    }
  }

  3. 图表类型动态切换

  前端支持在多种图表类型间动态切换：
  - 柱状图/条形图/折线图：可相互转换
  - 饼图：独立类型
  - 表格：原始数据展示

  切换逻辑：
  function onTypeChange() {
    nextTick(() => {
      chartRef.value?.destroyChart()
      chartRef.value?.renderChart()
    })
  }

  4. 数据处理与限制

  数据获取（ChartAnswer.vue:218）：
  function getChatData(recordId?: number) {
    chatApi.get_chart_data(recordId).then((response) => {
      // 将数据绑定到对应record
      record.data = response
    })
  }

  数据限制处理：
  - 后端限制最多返回1000行数据
  - 前端显示数据超限提示
  - 支持导出完整数据到Excel

  前后端数据交互流程

  1. 请求阶段

  用户输入自然语言查询
  → 前端发送POST /question请求
  → 后端创建LLMService实例
  → 开始流式处理

  2. 处理阶段

  数据源选择 → SQL生成 → SQL执行 → Chart配置生成 → 数据返回
  每一步都通过SSE实时推送到前端

  3. 渲染阶段

  前端接收SSE数据流
  → 解析不同类型的消息
  → 更新组件状态
  → 触发Chart重新渲染

  4. 交互阶段

  用户操作图表类型切换
  → 前端更新图表配置
  → 调用图表实例重新渲染
  → 无需后端参与

  核心特点

  1. 智能Chart推荐：LLM根据数据特征智能推荐最适合的图表类型
  2. 实时进度反馈：用户能看到SQL生成和Chart配置的完整过程
  3. 动态类型切换：前端支持多种图表类型的实时切换
  4. 数据量控制：合理限制显示数据量，保证性能
  5. 导出功能：支持Excel和图片格式的数据导出

  这个机制的核心优势在于将复杂的AI决策过程透明化，让用户不仅能看到最终结果，还能理解整个数据处理和可视化的过程。
